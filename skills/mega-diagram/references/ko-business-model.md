# 비즈니스 모델 (수익 구조도)

**쓰는 곳:** 사업계획서·IR·정부 지원사업 신청서의 "비즈니스 모델" 절. 자사 플랫폼을 가운데 두고 고객·파트너·공급자(·공공 지원)가 무엇을 주고받는지 두 종류의 흐름으로 그린다 — **서비스·가치**(실선)와 **돈**(점선, 금액·수수료율 라벨). 아래에 흐름이 모여 만드는 매출 목표를 한 줄씩 적는다.

**Base type:** [type-architecture.md](type-architecture.md) — 노드 박스(paper 마스크 + 스타일 박스), 직교 연결선, 16px 라벨 마스크. 박스 안 구성(역할 캡션 · 이름 · 구분선 · 글머리표)은 [type-governance.md](type-governance.md)와 같다.

## 쓰지 않는 곳

- **캔버스 9칸 전체**(핵심 파트너·활동·자원·가치 제안…): 표로 쓴다. 이 그림은 흐름만 그린다.
- **돈의 크기 비교**(어느 흐름이 얼마나 큰가가 요점): 생키 — [type-sankey.md](type-sankey.md).
- **시간 순서**(가입 → 설치 → 과금): 시퀀스나 프로세스 — [type-sequence.md](type-sequence.md), [type-process.md](type-process.md).
- **기관 간 협약·보고 관계**: 추진 체계도 — [type-governance.md](type-governance.md).

## Layout grammar

`0 0 1000 608` viewBox, 4px grid. 박스 폭 200.

| 노드 | x, y, w × h |
|---|---|
| 파트너 (위) | 400, 40, 200 × 88 |
| 고객 (왼쪽) | 40, 216, 200 × 112 |
| 자사 플랫폼 (가운데) | 400, 208, 200 × 128 |
| 공급자 (오른쪽) | 760, 216, 200 × 112 |
| 공공 지원 (왼쪽 아래, 선택) | 40, 432, 200 × 88 |
| 매출 요약 (오른쪽 아래) | 400, 432, 560 × 88 |
| 범례 | 헤어라인 y = 552, 기준선 584 |

- **흐름은 쌍으로, 같은 축에 40px 간격.** 가로 쌍은 y = 256(서비스, 위)과 296(돈, 아래), 세로 쌍은 x = 488(서비스)과 536(돈). 한 변에 붙는 두 선은 서로 다른 점에 닿는다(SKILL.md §6 규칙 4).
- **라벨 자리:** 위쪽 선의 라벨은 선 위(마스크 top = 선 − 24), 아래쪽 선의 라벨은 선 아래(top = 선 + 8). 세로 선은 옆에 8px 떼고 붙인다. 마스크는 박스 사이 빈 캔버스 안에 있어야 한다(규칙 6) — 박스 간격 160px이 라벨 폭 한도다.
- **파트너 → 고객**처럼 축이 다른 흐름은 `r = 8` 한 번 꺾인 경로(`M 400,84 H 148 Q 140,84 140,92 V 216`).
- **박스 안:** 역할 캡션(12px 500 `soft`) y + 22, 이름(12px 600) y + 42. 높이 88은 설명 한 줄(y + 66), 112 이상은 구분선(y + 56) + 글머리표(y + 78부터 18 간격).
- **매출 요약 상자:** 캡션 `2028년 매출 목표` + 합계(14px 600, 오른쪽 정렬), 아래 줄마다 `항목 · 산출식 · 금액`. 점선으로 들어오는 돈이 여기서 합쳐진다.
- **그리는 순서:** 흐름 선 → 라벨 → 박스 → 매출 요약 → 범례.

## Treatments

| 역할 | Fill | Stroke |
|---|---|---|
| 자사 플랫폼 (focal 1) | `accent-tint` | `accent` |
| 고객 | `input` (`muted @ 0.10`) | `soft` |
| 파트너 | `backend` (흰색) | `ink` |
| 공급자 · 공공 지원 · 매출 요약 | `ink @ 0.03` | `ink @ 0.30` |
| 서비스·가치 흐름 | — | `muted` 1.2 실선, `arrow` |
| 돈 흐름 | — | `muted` 1.2 점선 `5,4`, `arrow` |
| 핵심 수익 흐름 (focal 2) | — | `accent` 1.4 점선 `5,4`, `arrow-accent`, 라벨도 `accent` |

**Focal rule:** 플랫폼 박스 + 매출의 대부분을 만드는 돈 흐름 **하나**. 모든 돈 흐름을 파랗게 칠하면 "돈"이라는 범주가 되어 강조가 사라진다 — 범주는 점선이 이미 표시한다.

## Korean wording

- **서비스 라벨**: 주는 것, 명사 ≤ 8자(`검사 SaaS·키트`, `고객 발굴·설치`, `카메라·조명 부품`).
- **돈 라벨**: 금액이나 비율이 반드시 들어간다. `구독료 월 90만 원`, `대당 38만 원`, `판매 수수료 15%`, `도입비 50% 보조`. `결제`, `대금`처럼 숫자 없는 라벨은 금지.
- **단위**: 흐름 라벨은 단가(`만 원`), 매출 요약은 합계(`억 원`). 요약 줄의 산출식이 두 단위를 잇는다(`월 90만 원 × 1,200곳 × 12개월` → `130억 원`).
- **역할 캡션**은 모델 용어 그대로 `고객` · `파트너` · `공급자` · `공공 지원` · `자사 플랫폼`. 이름은 실제 주체(`중소 부품 제조사`, `SI 파트너사 8곳`).
- 마스크 폭 = 글자 폭 + 8, 4의 배수로 올림, 한도 152(박스 간격 160 − 여백).

## Complexity budget

- 참여자 ≤ 5(플랫폼 포함) + 매출 요약 1. 흐름 ≤ 10.
- 참여자 한 쌍 사이 흐름은 2개(서비스 1, 돈 1)까지. 세 번째가 필요하면 둘을 합치거나 매출 요약으로 보낸다.
- 강조 2개(플랫폼 + 핵심 수익 흐름).

## Anti-patterns

- **돈과 서비스를 같은 선 모양으로**: 두 흐름이 섞여 읽힌다. 실선/점선 구분이 이 그림의 문법이다.
- **금액 없는 돈 흐름.**
- **양방향 화살표 하나**(`↔`)로 주고받기를 표현: 무엇이 어느 쪽으로 가는지 사라진다. 한 쌍은 두 선.
- **쌍을 12px 미만으로 붙이기**, **사선 연결선**, **박스 뒤를 지나는 선**(SKILL.md §6).
- **매출 요약 숫자와 라벨 금액이 안 맞음.** 생성 스크립트에서 곱해 본다.
- **그림 번호·캡션을 SVG 안에** — [mega.md](mega.md).

## Pre-output checklist

- [ ] 플랫폼이 가운데, 참여자가 네 방향?
- [ ] 흐름 쌍이 같은 축에서 40px(최소 12px) 떨어져 있고 붙는 점이 서로 다른가?
- [ ] 모든 돈 흐름 라벨에 금액·비율이 있는가?
- [ ] 라벨 마스크 16px, 선에서 8px, 박스 사이 빈 캔버스 안?
- [ ] 강조는 플랫폼 + 핵심 수익 흐름 하나?
- [ ] 매출 요약 합계 = 항목 합, 항목 = 라벨 단가 × 수량?
- [ ] 범례: 자사 플랫폼 · 서비스·가치 · 돈 흐름 · 핵심 수익?
- [ ] light · dark · full 라벨이 같은가?
