# 도넛 차트 (Donut · 구성비)

**쓰는 곳:** 예산 비목 구성, 매출 구성, 인력 구성처럼 **한 합계를 3~6개 부분으로 나눈 구성비**를 한눈에 보여 줄 때. 연구과제 계획서의 `연차별 예산 구성`, 사업계획서의 `소요 재원 구성`이 대표적이다. 가운데에 총액을 두고, 조각마다 금액과 비율을 직접 단다.

**쓰지 않는 곳:**

- 부분끼리 크기를 정확히 비교해야 한다 → **막대** ([type-bar.md](type-bar.md)). 각도는 길이보다 읽기 어렵다.
- 부분이 7개 이상이거나 계층이 있다 → **트리맵** ([type-treemap.md](type-treemap.md)).
- 여러 해의 구성 변화 → **누적 막대** ([ko-stacked-bar.md](ko-stacked-bar.md)). 도넛 여러 개를 나란히 놓지 않는다.
- 합이 100%가 아닌 값(복수 응답 등) → 막대. 도넛은 부분의 합이 전체일 때만 정직하다.

**상속:** 부분-전체 규칙은 [type-treemap.md](type-treemap.md), 초점·값 라벨 규칙은 [type-bar.md](type-bar.md)를 따른다.

## Layout conventions

Canvas `viewBox="0 0 1000 448"`. 구조 좌표는 4px 격자, 호의 좌표는 데이터에서 계산하므로 격자 밖이어도 된다.

1. **링:** 중심 `(500, 204)`, 바깥 반지름 `R=144`, 안쪽 `r=92` (두께 52). 조각은 `<path>` 하나씩: 바깥 호(시계 방향) → 안쪽 호(반시계) → 닫기. 각도 = 값 / 합계 × 360°, 180°를 넘는 조각만 `large-arc=1`.
2. **순서와 시작 각:** 큰 비목부터 시계 방향. 시작 각은 **생성 스크립트가 고른다** — 같은 쪽 라벨끼리 세로 간격이 가장 넓어지는 각(최소 40px)을, 호 중점이 12시·6시 근처(|sin θ| < 0.35)에 오지 않는 범위에서 찾는다. 손으로 각을 정하지 않는다.
3. **조각 구분:** 각 조각에 `paper` 2px 테두리. 틈을 따로 비우지 않는다(각도가 값과 어긋난다).
4. **가운데 합계:** `2026년 총 예산` 12px 500 `muted` (baseline cy−12), 총액 `50.0억 원` 28px 600 `ink` (baseline cy+22). 총액은 조각 값의 합을 스크립트가 계산해 쓴다.
5. **직접 라벨 (필수):** 호 중점에서 바깥 반지름+6 위치에 r=2 점, 거기서 **수평** 지시선(1px)을 `cx ± (R+56)`까지 긋는다. 지시선 y는 점의 y와 같게 반올림하고 점의 x를 그 y에서 다시 계산하므로 선은 항상 수평이다(대각선 없음, SKILL.md §6-1). 라벨은 끝에서 8px 떨어져 두 줄: 비목 이름 12px 600 (baseline y+4), `13.5억 원 · 27.0%` 12px 400 `muted` (baseline y+22). 오른쪽은 `start`, 왼쪽은 `end` 정렬.
6. **범례 줄:** y=384 헤어라인, y=402에 `LEGEND`, 항목 baseline y=424. 색 설명(중점 비목, 기타 비목)과 오른쪽 끝 단위 문구 `단위: 억 원 · 비율은 총 예산 대비`. 범례는 보조일 뿐, 비목 이름은 모두 조각 옆에 있다.

## 색과 초점

| 역할 | 채움 | 비고 |
|---|---|---|
| 중점 비목 (1개) | `accent` 실색 | 이름·값 라벨과 지시선도 `accent` |
| 나머지 비목 | `ink` @ 0.56 / 0.36 / 0.22 / 0.12 | 큰 비목부터 진하게. 다크는 같은 투명도의 반전 ink |
| 구분선 | `paper` 2px | |

시리즈 팔레트(`series-*`)는 쓰지 않는다. 구성비에서 색 하나하나에 의미가 없으므로 잉크 농도 단계로 충분하고, 초점 하나만 파랗게 남는다.

## 한국어 표기

- 비목 이름은 보고서 용어 그대로: `인건비`, `연구장비`, `재료비`, `위탁연구`, `간접비`. 6자 이내.
- 값 라벨은 `금액 · 비율` 한 줄. 금액 `억 원` 소수 첫째 자리, 비율 소수 첫째 자리. **표시된 비율의 합이 100.0%** 가 되도록 데이터를 고르거나 끝수를 조정하고, 스크립트에서 assert한다.
- 단위 문구는 범례 줄 오른쪽 끝에 한 번만.

## Complexity budget

- 조각 3~6개. 7개 이상이면 작은 것들을 `기타`로 묶거나 트리맵으로.
- 가장 작은 조각 ≥ 5% (각도 18°). 그보다 작으면 라벨 간격을 지킬 수 없다.
- accent 요소 1개(중점 조각과 그 라벨).

## Anti-patterns

- **범례로만 읽게 하기.** 색 칩과 이름을 아래에 모아 두면 독자가 색을 맞춰 봐야 한다. 이름과 값은 조각 옆에.
- **대각선 지시선, 꺾인 지시선 여러 개.** 수평 한 줄로 끝나도록 시작 각을 고른다.
- **파이(가운데 꽉 찬 원), 3D, 조각 떼어 내기(explode).**
- **무지개 색.** 초점 하나 + 잉크 단계.
- **비율만 적고 금액을 빼기** — 보고서 독자는 금액을 찾는다.

## Checklist

- [ ] 부분의 합이 전체이고, 조각이 3~6개인가?
- [ ] 각도·총액·비율을 모두 같은 데이터에서 계산했는가? 표시 비율의 합이 100.0%인가?
- [ ] 모든 조각 옆에 이름과 `금액 · 비율`이 있는가? 지시선은 수평인가?
- [ ] 같은 쪽 라벨 사이 세로 간격 ≥ 40px, 라벨이 캔버스와 범례 줄 안쪽인가?
- [ ] accent는 중점 조각 하나뿐인가? 한글 12px 이상인가?
