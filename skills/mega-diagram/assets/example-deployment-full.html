쇼핑몰 주문 서비스 · 운영 배포

조회는 엣지 캐시가 흡수하고, 인그레스 뒤 API 파드 3개가 주문 쓰기를 처리하며, Postgres 주 DB 1대가 데이터 영역의 대기 DB로 WAL을 스트리밍.

THE HEADLINE

주 DB 1대, 단일 장애점 1곳

모든 주문 쓰기는 주 DB로 집중. 대기 DB는 WAL을 계속 받지만 즉시 전환(hot) 상태는 아님 — 주 DB 장애가 이 구성에서 아직 자동화하지 못한 유일한 시나리오.

인그레스 1개 뒤의 복제본 3개

  • order-api 파드 복제본 3개 운영
  • sidecar-otel이 같은 파드에서 트레이스 전송
  • nginx-ingress가 요청을 3개 파드로 분산

정적 조회는 엣지에서 흡수

Cloudflare 엣지 캐시가 캐시된 응답을 직접 반환. 캐시 미스와 쓰기 요청만 인그레스 영역에 도달.
